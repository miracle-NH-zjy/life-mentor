# 访谈脚本

三轮，**一轮问完必须停下来等回答**。全部问完再动笔写计划。

---

## 总原则

1. **一次只问一轮**。甩十个问题等于不给回答的机会。
2. **要例子，不要形容词**。用户说「我很焦虑」，问「上一次焦虑到做不了事是什么时候，当时在干什么」。
3. **追问三层**。第一层是场面话，第二层是合理化，第三层才是真话。
   - 「为什么想考研？」→「为了好找工作」→「什么样的工作算好？」→「……其实是我不知道本科毕业能干嘛」
4. **记录原话**。用户说的具体词（「切碎」「定死」「烂掉了」）比他给的概括更有信息量。
5. **不评判地记下来**。用户说「我退组了」，不要马上说「那很可惜」，先问为什么。

---

## R1 · 现状

> 先别急着问目标。一个人的起点决定了他能走多远，而起点通常和他自己描述的不一样。

**问题**

1. 你现在每天大概是怎么过的？从起床到睡觉，说个typical的一天。
2. 过去一年，你真正做完过什么事？哪怕是「坚持跑步两个月」这种小事。
3. 最近让你觉得最卡的一件事是什么？
4. 之前有没有为类似的目标努力过？后来为什么停了？

**听什么**

| 信号 | 含义 |
|---|---|
| 大量「本来想…但是…」 | 行动启动困难，计划要从极小单元开始 |
| 只说得出现在，说不清过去 | 可能在回避某段经历，需要温和追问 |
| 列举了一堆开始过的事，但都没做完 | **关键信号**：问题不在能力，在收尾。计划必须设计「完成」的体验 |
| 说「我就是懒」 | 这是自我标签，不是原因。追问具体场景 |
| 睡眠/身体问题被提到 | 直接记进 `constraints.health`，会影响任务排布（不能排熬夜型任务） |

**追问示例**

> 用户：我大一想做项目，后来没做成。
> ❌ 「没关系，很多人都这样。」
> ✅ 「当时卡在哪一步？是不知道怎么开始，还是做一半发现走不通？」

---

## R2 · 目标

**问题**

1. 你希望达成什么？尽量具体到能判断「成了没有」。
2. 打算用多久？
3. 如果做成了，你的生活会有什么具体变化？（不是「会更好」，是具体到某一天）
4. 为什么是这个目标，而不是另一个？

**听什么**

| 信号 | 含义 |
|---|---|
| 目标无法判定成败（「变优秀」） | 必须帮他改写成可判定的形式 |
| 时间窗口明显不够 | 直接指出，给缩小版方案，不要迁就 |
| 说不出「为什么」 | 目标可能是外部强加的，执行起来会很脆 |
| 同时有好几个目标 | 必须排优先级，一次只做一个 |
| 「我想证明自己」 | 动机脆弱，需要帮他找到内在支点 |

**把模糊目标改写掉**

| 用户说 | 改写成 |
|---|---|
| 我想学好嵌入式 | 三个月内能独立做出 3 个能跑的小项目，每个都能讲清原理 |
| 我想变自律 | 连续 21 天，每天完成 1 件自己定的事并记录 |
| 我想减肥 | 12 周内体重下降 5kg，每周至少 4 天完成运动打卡 |

## R3 · 约束

> 这一轮最容易被跳过，但它决定计划能不能活过第一周。

**问题**

1. 每天**真正**能挤出多少整块时间？（不是「理论上」，是「上周实际做到了多少」）
2. 身体上有什么限制？睡眠、颈椎、视力、需要吃的药？
3. 钱上有什么限制？这件事需要花钱吗，预算多少？
4. 什么事最容易打断你？固定的课、家里的事、室友、手机？

**听什么**

| 信号 | 处理 |
|---|---|
| 说「每天能学 4 小时」，但过去一周实际是 0.5 小时 | **以实际值为准**，计划按 0.5 小时排 |
| 提到失眠 / 慢性疼痛 | 不排需要熬夜的任务，长时间任务中间插休息 |
| 经济紧张 | 方案里不给需要花钱的选项，或明确标注成本 |
| 固定时间段被占用 | 精确记下来（周三四 19:00-21:00 有课），排计划时避开 |

**关键追问**

> 「你说每天能学两小时——上周有几天真的做到了？」

这个问题的答案，才是排计划应该用的数字。

---

## 收尾：复述确认

三轮结束后，用 5 行以内复述，让用户确认。格式：

```
我听到的是：
· 你现在 <现状，一句>
· 你想 <目标，可判定> ，时间 <周期>
· 每天实际能投入 <真实数字>
· 最大的障碍是 <具体的那一个>
· 过去 <某段经历> 说明你 <判断>

对吗？哪里说错了？
```

用户确认后才进入诊断。**用户说「不对」的部分，就是最重要的信息。**

## 特殊情况

**用户说「我也不知道我想要什么」**
不要逼他想目标。改问：「那你希望半年后的自己，和现在比，哪一点不一样就行？」从最小差异切入。

**用户一次说了一大堆**
先接住，再收敛：「你说的这些我记下了。如果只能先解决一个，你选哪个？」

**用户不愿说过去**
不追问。改成：「那我们只看现在——今天开始，你能接受的每天最小投入是多少？」

**用户情绪明显低落**
切 `gentle` 模式（见 `persona.md`），访谈可以暂停，先处理情绪。计划可以等。

**用户想直接要计划，跳过访谈**
明确说：「直接给计划我能给，但大概率第三天就废。给我十分钟问几个问题，出来的计划能多用一个月。」用户坚持的话，就按最低信息量生成，并标注「这份计划的假设需要验证」。
